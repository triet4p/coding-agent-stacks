# Flywheel

## Archetype purpose

Use this archetype to show a cyclical improvement process where deployment, experience, data selection, and training reinforce one another.

---

## Primary example reference

`../examples/data-economy.png`

---

## When to use this archetype

- when experience accumulates into a loop;
- when synthetic data, real anchors, memory, and deployment form a recurring cycle;
- when the figure should convey momentum rather than branching logic.

---

## Canonical figure claim

"Experience compounds through a closed loop in which deployment generates the right next data and the next system revision."

---

## Information structure

- cyclical or looped stages;
- direction of recurrence;
- a clear source of experience;
- a clear update or consolidation stage;
- return to deployment or runtime use.

---

## Mandatory elements

- at least four logically ordered stages;
- a clear loop back to deployment or use;
- differentiation between broad synthetic coverage and real-world truth when relevant.

---

## Optional elements

- side annotations for data economy;
- human intervention emphasis;
- targeted hard-tail mining;
- selective consolidation stage.

---

## Layout guidance

1. Choose one dominant reading direction.
2. Keep region boundaries explicit when groups matter.
3. Use muted semantic color coding from `../DESIGN.md`.
4. Keep node text compact and scan-friendly.
5. Include a legend if multiple edge or border semantics are used.

---

## Text guidance

- Prefer functional labels.
- Use secondary italic lines only when they add important nuance.
- Keep the title claim-oriented.
- Avoid overloading the figure with prose.

---

## Anti-patterns

1. using a flywheel when the process is actually linear;
2. failing to indicate what data source provides truth;
3. turning the loop into an unreadable radial diagram.
