# One-Shot Progress Supervision

Main reads this protocol when launching the first active flow attempt. Workers/reviewers use the progress-response contract in their own role/skill; they need not preload this Main-only reference.

- For every active attempt, start exactly one finite background shell timer with an adaptive observation interval of **10–45 minutes**. Use an existing finite async shell timer (for example, PowerShell `Start-Sleep` through Bash with async enabled) emitting task ID, attempt ID and timer-generation ID. This is an observation prompt, not a worker deadline or a reason to stop work.
- Choose the interval from task context and observed progress. Keep only one timer generation active per attempt; never rearm in a hot loop.
- On attempt completion, completion takes precedence: cancel any active timer and invalidate its generation. If completion races with a timer, process completion first. Ignore stale task/attempt/generation events. Cancel timers for attempts paused for an owner decision and rearm only on authorized resumption.
- On a current timer event, send exactly one outstanding `progress_request` with `task_id`, `attempt_id`, `agent_id`, `progress_request_id`, and `timer_generation`. Do not send another while a reply is pending. For implementation workers only, include `advisor_offer: "Bạn cần advisor gì không?"` when no advisor request/interest/consultation or evidence reviewer is active. Worker plus reviewer occupy both slots. Reviewers and checkpoint executors never receive the offer.
- The matching reply contains those IDs plus `stage`, `completed_since_last_report`, `new_evidence`, `current_blocker`, `attempts`, `results`, `next_action`, and `help_needed`. Implementation workers also return `advisor_needed: false|true` and may supply one qualified request. A true flag without a complete request is pending interest, not permission to launch. Reviewers and checkpoint executors do not request advisors.
- Compare evidence and deltas, not elapsed time alone. Progress, timer and delivery events never establish completion or a gate verdict. After a matching reply, if the attempt is still active with no pending request, start the next one-shot generation at an adaptive 10–45-minute interval.
- After roughly 4–5 matched exchanges, reassess progress, blocker and next safe action. This does not override review-round limits or an early gate-reconsideration stop. Follow `replacement-and-handoff.md` only when pause/replacement is actually needed; do not repeatedly poll or use eval wait barriers for supervision.
